# Roshen · Адаптація

Портал адаптації нового співробітника. Мапа епізодів нагадує шлях у casual-грі: світи, кроки, зірки, святковий фінал. Механіка обслуговує онбординг, а не навпаки: немає життів, енергії, таймерів очікування, штрафів і публічного рейтингу швидкості.

Інтерфейс українською. Дані демонстраційні. Прогрес цього браузера лежить у `localStorage`.

## Як відкрити

Після публікації GitHub Pages:

- портал: <https://fominvo.github.io/test1/roshen-onboarding/>
- наявне демо speech-to-speech лишається на корені сайту: <https://fominvo.github.io/test1/>

Локально з теки `roshen-onboarding`:

```bash
npm install
npm test
npm run dev
```

Збірка для Pages: `npm run build`. Vite кладе відносні шляхи (`base: './'`), тож сторінка працює в підкаталозі репозиторію. У workflow сторінки `s2s-demo` копіюється в корінь артефакта, а `dist` порталу — в `roshen-onboarding/`.

Демо-дата зашита в `public/data/content.json` (`meta.asOf`, 19 жовтня 2026). У кабінеті HR її можна зсунути, щоб побачити календарні ворота світів.

## Структура

| Шлях | Навіщо |
| --- | --- |
| `public/data/content.json` | Люди, світи, кроки, зустрічі, щоденні дарунки. Це файл HR. |
| `public/data/rewards.json` | Зірки, ворота світів, цукерки, бустери, відзнаки. |
| `public/assets/manifest.json` | Який файл мапи, маскота, іконок і відзнак показувати. |
| `public/assets/creative/` | Оптимізовані WebP. Оригінали згенеровано для цього проєкту. |
| `src/logic.js` | Правила зірок, серії, світів, пульсу. Без DOM. |
| `src/views/` | Мапа, крок, профіль, магазин, календар, кабінет HR. |

Світи: 0 Преонбординг, 1 Перший день, 2 Перший тиждень, 3 Перший місяць, 4 60 днів, 5 90 днів. Окремий горизонт — пульс 365 днів. Типи кроків: читання, відео-глави, квіз, зустріч, чекліст, пульс і бонус «Солодка лінія» (три в ряд).

## Як редагувати контент

1. Відкрийте `public/data/content.json`.
2. Людина — об’єкт у `people` з `kind: "hire"`, датою старту, buddy і керівником. Поле `seed` задає стартовий прогрес демо.
3. Крок — об’єкт у `levels`. `worldId` (`w0`…`w5` або `horizon`), `type`, `dueDay` (день 1 = перший робочий день), `icon`, текст.
4. Зустріч потрапляє в календар, якщо є `meeting` або тип `meeting` / `pulse`. Дата зсувається на найближчий робочий день: понеділок–п’ятниця, без державних свят України (ст. 73 КЗпП, включно з 1 січня) і без перенесеного вихідного, якщо свято припало на суботу або неділю. Щотижневі зустрічі з buddy стоять у четвер о 16:00; якщо цей четвер вихідний, обирається найближчий робочий день. Час лишається в межах 09:00–18:00. Кнопка «Додати в календар» збирає `.ics` уже зі зсунутою датою.
5. Щотижневі зустрічі з buddy: `"buddyWeekly": true`. Лічильник рахує їх сам.
6. Рутинний чекліст, який можна закрити бустером: `"routine": true`. Навчання, безпека, зміна на фабриці і зустрічі так не позначайте.
7. Економіку (пороги зірок, 70% воріт, ціни) міняйте в `public/data/rewards.json`, не в компонентах.
8. У кабінеті HR є завантаження JSON у цей браузер. Для всіх колег файл має лежати в репозиторії.

`done: "*"` у seed означає «усі небонусні кроки». Інакше перелічіть id.

## Ассети

Маніфест `public/assets/manifest.json` вказує на WebP. Якщо файл не відкриється, інтерфейс малює SVG-заглушку.

| Ключ | Файл | Де видно |
| --- | --- | --- |
| `mapBackground` | `assets/creative/map.webp` | Фон шести епізодів |
| `worldBackground` | `assets/creative/world_bg.webp` | Горизонт 365 |
| `mascot` | `assets/creative/mascot.webp` | Гід Пралінка |
| `levelComplete` | `assets/creative/level_complete.webp` | Екран закритого кроку |
| `icons.*` | `assets/creative/icons/*.webp` | Вузли мапи і календар |
| `badges.*` | `assets/creative/badges/*.webp` | Відзнаки в профілі |

Щоб підставити роботу дизайнера, замініть WebP за тим самим шляхом або оновіть рядок у маніфесті. Пралінка, мапа і відзнаки — окремі ілюстрації цього проєкту, не персонажі чужої гри.

Офіційний словесний знак Roshen у шапці і на заставці взято з SVG у шапці [roshen.com](https://www.roshen.com/) (`themes/roshen`, клас `logo-svg`). Палітра з того самого сайту: чорнило `#0d0f17`, золото `#fee597` (ховер логотипа), крем `#f0e8c1` / `#f7f1e4`, сланець `#4b5064`. На сайті текстовий шрифт — Myriad Pro; його файли не копіюємо. В інтерфейсі самохостяться відкриті шрифти з кирилицею: Onest для заголовків і Source Sans 3 для тексту (гуманістичний гротеск, близький за характером до Myriad). Мапа — вертикальна колонка близько 620px (на телефоні на всю ширину), праворуч лишається календар. Фон сторінки — одне зображення `world_bg` на весь екран через `object-fit: cover`, розмите і притемнене, без розтягування. Кожен епізод у колонці має свій портретний фон з `assets/worlds/world1.webp`…`world6.webp` (`object-fit: cover`, без розтягування). Між епізодами короткий м’який перехід. Стежка — глянцева карамельна SVG-дорога по центру кадру, вузли стоять на ній. За колонкою — розмита копія поточного світу.

PNG з коміту артів конвертовано у WebP (мапа лишилась 864×1536). Сумарна вага творчих файлів тримається значно нижче 2 МБ.

## Економіка

- 1 зірка — крок закрито вчасно.
- 2 зірки — без нагадування або квіз від 80%.
- 3 зірки — buddy чи керівник підтвердив якість у кабінеті HR, або є коротка рефлексія.
- Наступний світ відкривається на 70% зірок попереднього **або** в свій календарний день. Ніхто не застрягає.
- Цукерки нараховуються за кроки, зірки і підтримку колег. Їх витрачають на підказку, контакт експерта, пропуск рутини і на заявку HR (набір Roshen, мерч).
- Серія днів заморожується на вихідних, лікарняному і відпустці. Пропуск звичайного дня ставить її на паузу, але не обнуляє.
- Відзнаки лише за події: перший день, зміна на фабриці, перша щотижнева зустріч із buddy, перший тиждень, чекпоінти 30, 60 і 90.
- Немає таблиці лідерів, втрати прогресу і життів. Інші новачки стоять на мапі своїми аватарами. Спільна ціль когорти — один квіз про продукцію.

## Навіщо так

Онбординг тримається на моделі 4C Талії Бауер: відповідність, прояснення, культура, зв’язок. Кожен крок позначений однією з опор. План розкладений на преонбординг і вікна 30/60/90, з окремим пульсом ще й на 365-й день.

**Google re:Work і Laszlo Bock, «Work Rules!».** У re:Work описано, що онбординг міряють повторно, а не один раз у перший тиждень: опитування на 30, 90 і 365-й день за трьома зонами — інструменти, продуктивність і навички, культура і зв’язок ([гайд re:Work](https://rework.withgoogle.com/intl/en/guides/a-data-driven-approach-to-optimizing-employee-onboarding)). У «Work Rules!» Bock розповідає про лист керівнику напередодні першого дня з п’ятьма простими діями: обговорити роль, призначити buddy, допомогти з колом людей, поставити щомісячні check-in на пів року і відкрити діалог. Саме цей «рівень 0» живе в кабінеті HR, ще до дня 1. Окреме самонагадування новачка на другому тижні (питання, фідбек, регулярні 1:1) — той самий принцип вчасного поштовху, тільки з боку людини, яка щойно вийшла.

**Microsoft, HBR, 2019.** Dawn Klinghoffer, Candice Young і Dave Haspas описали пілот buddy на 600 людях ([Every New Employee Needs an Onboarding “Buddy”](https://hbr.org/2019/06/every-new-employee-needs-an-onboarding-buddy)). Користь росла разом із кількістю зустрічей за перші 90 днів, аж до понад восьми розмов. Тому на мапі щотижневі зустрічі з buddy — окремі кроки, а в профілі є лічильник, не бейдж «просто познайомились».

**Zappos, HBR, 2008.** Онбординг Zappos будувався як занурення в культуру, а не як папка політик. Епізод «Зміна на фабриці / дегустація» у світі першого дня — та сама ідея для кондитерської компанії: людина проживає продукт і зміну, а не лише читає про них.

Пульс навмисно не карає. Низька оцінка культури лишається сигналом для HR і не знімає зірки.
